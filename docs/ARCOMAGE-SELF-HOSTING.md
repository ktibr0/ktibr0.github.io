# ArcoMage HD: как разместить игру у себя

## Цель

Кнопка на «Игротеке» открывает `/arcomage-hd/` на `ktibr0.github.io`. HTML, исполняемый JS, изображения, звук и русский язык загружаются с собственного сайта. Одиночная игра не зависит от доступности `arcomage.github.io`. Переписывать игровую механику не требуется.

## Что обнаружено локально 16.10.2026

- Папка `arcomage-hd/`: index, JS/CSS bundles в assets, локали/изображения, manifest, иконки, SW/Workbox, LICENSES.txt; внутри ещё одна папка `dist/`.
- В обследованной папке нет полного дерева `src`, TypeScript, `package.json`/lockfile и конфигурации сборки. Это пригодный для исполнения дистрибутив, но не подтверждённый полный исходный проект для пересборки. Нельзя делать вывод об отсутствии исходников в других каталогах пользователя.
- Корневой `index.html` этой игры адресует `src="/assets/..."`, manifest и SW register от корня сайта. При URL `/arcomage-hd/` такой путь означает `https://ktibr0.github.io/assets/...`, а файлы лежат глубже.
- `registerSW.js` регистрирует `/sw.js` со scope `/`. Здесь нужен собственный worker внутри `/arcomage-hd/` и ограниченная область, а не обслуживание всей «Игротеки».
- Manifest уже содержит `start_url: "./"`, `scope: "."`; это не отменяет проверки пути самого manifest, иконок и сгенерированного SW.
- Главная Игротеки пока ссылается на внешний сайт. Локальная копия не используется этой кнопкой.

## Два пути

### A. Адаптировать имеющийся дистрибутив

Подходит для быстрой пробы сохранённой версии. Сначала составить полный список зависимостей и выбрать одну из копий как фактический output, сохранив остальные. Исправить base URL в HTML, динамических JS-imports/путях media, CSS, manifest, precache и навигационном fallback. Редактирование только index недостаточно. Проверить все переходы, а не только первый экран.

Плюс — можно начать с уже имеющихся файлов. Минус — minified bundles и generated SW неудобно поддерживать; для воспроизводимости нужен небольшой сохранённый инструмент адаптации и manifest входных hashes, а не ручные глобальные replace. Исходную сборку не перезаписывать до результата проверки; промежуточную адаптацию хранить в `_work/arcomage/`.

### B. Пересобрать из upstream-исходников (предпочтительно для сопровождения)

Официальный проект: <https://github.com/arcomage/arcomage-hd>, [README](https://github.com/arcomage/arcomage-hd/blob/main/README.md). Это источник для будущего получения кода, а не уже установленная локальная зависимость.

1. По возможности найти исходный проект у пользователя; иначе получить upstream в отдельный рабочий каталог. Проверить вложенные Git-репозитории: не коммитить checkout как случайный gitlink. Для проекта выбрать явный способ хранения исходников/patches и воспроизводимой сборки; не создавать незапрошенный отдельный Forgejo repo.
2. Зафиксировать commit/tag, runtime/package manager и lockfile. Не обновлять автоматически до latest: локальная копия может относиться к другому выпуску; сначала определить/сопоставить версии.
3. Прочитать реальные build scripts/config выбранной версии. Установить deployment base `/arcomage-hd/` либо эквивалентную относительную схему, поддерживаемую проектом. Не предполагать имя настройки без проверки; entrypoint выглядит как Vite output, но полный config ещё не обследован.
4. Собирать в staging output; проверить asset paths, динамические chunks, русский язык, media, manifest и SW. После приёмки публиковать итоговые статические файлы в `arcomage-hd/`; Node нужен для сборки, а не посетителям сайта.
5. Записать источник/commit, команды, patch и способ обновления в будущий `arcomage-hd/README.md` или отдельный build-manifest.

Выбор A/B подтвердить короткой технической пробой. Пока ни один путь не реализован; утверждать «исходники уже все есть» или «нужен собственный игровой сервер» оснований нет.

## Область автономности

Собственный хостинг = доступная одиночная игра со своими ресурсами. Наличие ссылки на автора/исходники не означает runtime-зависимость. Multiplayer через WebRTC отдельно может использовать signaling/STUN: upstream это прямо описывает. Нет задачи делать сетевую игру автономной. См. [официальный README, раздел Multiplayer](https://github.com/arcomage/arcomage-hd#multiplayer-mode).

Русский язык и игра против ИИ уже заявлены upstream; не нужно писать собственный перевод/ИИ до проверки существующих настроек. См. [официальное описание](https://github.com/arcomage/arcomage-hd#arcomage-hd---open-source-card-game).

Не считать весь набор изображений/звуков автоматически MIT по лицензии кода: сохранить авторов, LICENSE/NOTICES и проверить условия именно ресурсов. Текущий LICENSES.txt во многом содержит notices библиотек.

## Service worker и сохранения

- Script URL и scope не шире `/arcomage-hd/`. У worker собственные имена/version кешей. Не удалять все CacheStorage/localStorage сайта и не ставить навигационный fallback для `/cryptographer/`, `/sumplete/`, `/rsvp/`.
- Предусмотреть обновление SW: новая версия ресурсов, выход из старого кеша, повторное открытие и offline после прогрева. Не обещать offline в совершенно новом браузере без предварительной загрузки.
- Настройки/сохранения внешнего `arcomage.github.io` принадлежат другому origin; наша страница не может автоматически читать их. Если перенос важен, искать штатный export/import, без обходов защиты браузера.

## Приёмка до изменения ссылки в меню

1. Чистый browser context с пустым кешем, блокировка запросов к `arcomage.github.io`. Загрузка страницы, картинок, RU locale, меню, ИИ и начало партии работают.
2. Выполнить реальный допустимый ход и сброс карты на touch; проверить ошибки/disabled controls, звук и mute, настройки/возврат. Записать все неуспешные HTTP/console/page errors и обязательные запросы к другим хостам. Проверить первый и последующие lazy imports.
3. После прогрева отключить сеть и повторить одиночный сценарий; полностью закрыть/открыть страницу. Отличать поддержку offline от переноса/сохранения конкретной незавершённой партии, который ещё надо исследовать.
4. Chromium и WebKit, планшет 1024×768/1180×820. Portrait 412×915/360×800: честная просьба повернуть допустима на первом этапе; полноценный portrait redesign — отдельный объём.
5. На том же origin открыть Криптограф и Sumplete: SW ArcoMage их не перехватывает, сохранения не исчезли. Jelly Battle не использовать как объект этой работы.
6. Только после успеха заменить `href` ArcoMage в корневом `index.html`; новый внешний origin/домен и backend не нужны. Опубликовать и проверить сценарий на фактическом Pages.

## Следующая конкретная задача

Провести read-only inventory двух локальных сборок и пробу запуска из подпапки, затем оформить решение A/B с перечислением изменяемых файлов и tests. Не начинать с переписывания интерфейса или массовой замены абсолютных URL.
