Цель: одиночная ArcoMage по `/arcomage-hd/` на существующем GitHub Pages, с русским языком, собственными изображениями/шрифтами/звуками и автономной работой после предварительной загрузки. Игровую механику и версию не обновляем. Jelly Battle, её карточку/ZIP и общий Ruffle не изменяем.

Выбран вариант A: сохранённый `arcomage-hd/dist/` остаётся неизменным входом для небольшого детерминированного адаптера; исправленный результат находится в `arcomage-hd/`. Это не пересборка из upstream-исходников. Upstream tag object v2.0.3: `604587133cc61c6af0f88314ad42bad930d070df`, исходный commit: `efa3ea4120ce2aef4625c50d492a733cf3afbbf7`; соответствие сохранённого дистрибутива этому исходному коммиту не доказано.

## Файлы и критерии

- `tools/arcomage-adapt.cjs`, `arcomage-hd/build-manifest.json`: исходные хеши, воспроизводимые точечные изменения URL, полный перечень результата.
- `arcomage-hd/index.html`, JS/CSS и SW: исправить корневые пути, включая lazy preload; worker и кеши ограничить `/arcomage-hd/`, собственный namespace, очистка только собственных версий. Предварительно сохранить все игровые ресурсы и языки. Соседние игры не перехватывать.
- `arcomage-hd/README.md`, `CREDIT.md`, прежний `LICENSES.txt`: происхождение, способ повторения, условия авторов. MIT кода не распространяется автоматически на оригинальные игровые ресурсы; upstream отдельно описывает их copyright и использование.
- `tests/arcomage/`: независимые проверки, написанные основным агентом до приёмки; Luna 6 low запускает их без изменения ожиданий.
- `index.html`, `papergames/index.html`: переключить только ссылки ArcoMage после локальной приёмки. Для обновления сохранённого каталога синхронно повысить его cache version в `papergames/sw.js` и `library/offline.js`. Игровые файлы PaperGames не меняются. Затем TODO/HANDOFF/README и эта запись отражают фактический результат.

Приёмка: чистые Chromium/WebKit с блокировкой внешних HTTP-запросов, RU и языковые chunks, меню/настройки, старт против ИИ, настоящий ход и сброс, касания, звук/mute, повторное открытие, автономная работа после прогрева; разные размеры планшета и телефона, визуальный просмотр. Отдельно сохранить контрольные данные и кеши соседних приложений, открыть Криптограф и Sumplete, проверить scope и отсутствие перехвата. Автономность проверять также при реально недоступном origin, поскольку WebKit setOffline ранее давал ложные результаты.

## Результат

Реализация принята локально. ArcoMage: static PASS, 18/18 Chromium/WebKit (`_work/arcomage/local/stable-game/results.json`), оба движка прошли новое открытие и два игровых действия с реально выключенным origin. Четыре перехода из обоих каталогов — 4/4. Регрессия Криптографа — 12/12 правила и 28/28 браузер. PaperGames — static PASS и итоговые 26/26 Chromium/WebKit, включая полный offline-пакет, неоткрытые игры/правила, сохранения, foreign caches и обновление.

Основной агент просмотрел изображения обоих движков: планшетные 1180×820, 1024×768/600, вертикальный телефон с просьбой поворота и загруженный офлайн дополнительный язык. Игровое оформление сохранено. В первом полном прогоне PaperGames был один `Context is stopped` в WebKit при многократной офлайн-навигации; повтор без изменения кода/тестов прошёл 26/26. Оба прогона сохранены, причина этого единичного runtime-сбоя не установлена.

Публикация ещё не подтверждена. Физические iPad/Android в этой сессии не проверены. Перенос сохранений с внешнего origin и автономный multiplayer не входят в этот этап.

## Разбор первоначальных сбоев

- В Windows headless WebKit нет AudioContext: исходный дистрибутив падал при импорте звукового модуля. Добавлены пять проверяемых точечных защит: при отсутствии/ошибке создания Web Audio игра продолжает работать без звука; обычный аудиопуть и правила не меняются. В тестах нет глобальной подмены AudioContext; Chromium запускает настоящие native sound sources. Слышимый звук на физическом устройстве не проверен.
- Worker читает кеш без создания нового в fetch handler, чтобы старые запросы после обновления не создавали удалённый кеш вновь. Очистка ограничена собственным namespace.
- Начальные сценарии неверно ожидали правый клик в touch mode (upstream использует удержание), одну фиксированную позицию сыгранной карты и другое имя немецкой кнопки. Исправлены сценарии по исходному обработчику и реальной локали. DOM long-press проверяет обработчик, но не заменяет проверку жеста на планшете.
- Асинхронную приёмку обновления выполняем явным ожиданием завершения install/activate и полного нового кеша, а не появления его имени. Неуспешные прогоны сохранены.
- Windows WebKit теряет CacheStorage entries при навигации создавшего их документа даже без ArcoMage/worker. Это воспроизведено в отдельных `probe-webkit-cache-storage*.json`. Исправленная fixture держит открытым документ другого приложения и проверяет его реальную запись из других вкладок; контроль `probe-webkit-cache-owner.json` подтверждает сохранность. Проверка чужих данных не исключена из приёмки.
- Для smoke с настоящими случайными картами через настройки заданы высокие начальные стены/башни и пороги победы: это отделяет два проверяемых действия от случайного раннего завершения партии. Сами карты/ИИ/правила не подменяются.
- `.gitattributes` закрепляет исходные CRLF и LF генерируемых файлов для воспроизводимости на Windows; manifest хранит raw checkout SHA и отдельный `publishedSha256` нормализованных Git/Pages файлов.
