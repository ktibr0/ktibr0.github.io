# Игротека: правила работы

## Начало работы

Прочитать `README.md`, `TODO.md`, `docs/HANDOFF.md`; для выбранного этапа — соответствующий технический план. Рабочий Git-каталог — этот каталог, а не родительский GameCenter. Перед изменениями проверить статус, remotes и последние коммиты. Не путать опубликованные возможности и TODO.

## Назначение и ограничения

Семейная подборка игр на GitHub Pages. Родители вдвоём решают одну задачу на 10-дюймовых планшетах: Android/Chrome и iPad/Safari, преимущественно альбомная ориентация. Пользователь также играет на Samsung S24 Ultra вертикально. Не нужны профили «мама/папа», соревнования, рейтинги или обязательный таймер. Сохранять знакомые правила и спокойное оформление, делать крупные читаемые элементы.

Статический сайт: HTML/CSS/JS, CSV, WebAssembly и ресурсы; допустима предварительная сборка, но результат должен запускаться на Pages без постоянно работающего backend. Не вводить фреймворк или внешние API без конкретной необходимости. Для общей партии использовать локальное сохранение с обработкой ошибок хранилища.

## Запрещённая область: Jelly Battle

По прямому указанию пользователя НЕ менять `jellybattle/**`, `jellybattle.zip`, правила, SWF и ресурсы Jelly Battle, не заменять игру другой реализацией и не заниматься её переносом. Эта игра переписывается отдельно. Существующую ссылку и карточку сохранить. Общие стили главной могут затрагивать оформление карточек целиком, но не менять ссылку/содержание/поведение Jelly Battle.

`jellybattle/index.html` использует `rsvp/ruffle/ruffle.js`. Поэтому в текущем плане НЕЛЬЗЯ обновлять или заменять общий каталог `rsvp/ruffle/**`: это косвенно меняет Jelly Battle. Улучшения RSVP ограничить его оболочкой; если потребуется другой runtime, сначала запланировать отдельную копию для RSVP с отдельными путями и без изменения прежней.

## Модели, тесты и маленькие этапы

Сохранить выбранную пользователем схему: основной агент разрабатывает план по файлам, критерии и тесты, интерпретирует результаты и проводит ревью. Исполнение изменений и запуск тестов делегировать отдельным Luna 6 medium (`gpt-6-luna`, reasoning `medium`). Передать исполнителям ограниченные файлы; не давать им менять тесты ради зелёного результата. Документацию/критерии основной агент может вести сам. Независимые задачи параллелить только без общих изменяемых файлов.

Не соединять структурный рефакторинг, изменения правил и редизайн в один непрозрачный этап. У каждого этапа должны быть проверяемый результат, тесты по риску и отдельный осмысленный коммит. Не писать тесты для чисто редакционных изменений. Обязательны Chromium + WebKit и ручной просмотр изображений для изменения интерфейса; headless WebKit не равен физическому iPad. Не объявлять Flash-игру работоспособной по одному загрузочному экрану.

## Сохраняемые контракты Криптографа

Рабочий выпуск `f24dfce`: открывается одна выбранная клетка; одинаковая буква имеет один код; отсутствующие буквы приглушены и отключены; три жизни, подсказки 5/3/2; подсказка открывает выбранную клетку. Одна общая партия и колода сохраняются через localStorage. CSV `id,text,author,category`, UTF-8, запятые; ID не меняются при перестановке. Не добавлять поиск/генерацию цитат через внешний API. Не возвращать 3D-backface-карточки: в WebKit скрытые буквы становились видимыми; закрытые DOM-карточки не должны содержать текст ответа.

## Материалы и отчётность

Не удалять скрипты, тесты, расчёты, промежуточные результаты и снимки до явного завершения проекта пользователем. Локальные артефакты хранить в `_work/<этап>/` (ignored); ключевые выводы, обезличенные fixtures и способы повторения — в docs/tests.
